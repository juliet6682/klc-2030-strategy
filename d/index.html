Three Audiences · One Strategy

三種角色，同一條管理鏈

同一份內容依角色切換閱讀深度：董事會看選擇與治理，主管看承接與執行，職員看方向與行為。

董事會｜策略說明

以 A→B 為主，確認我們要去哪裡、真正瓶頸是什麼、資源應集中在哪些選擇；再用 C 檢查執行組合是否支撐戰略。

主管｜戰術溝通

以 B→C→D 為主，把戰略轉成部門生產型／發展型戰術，建立 Owner、時程、交付物、完成指標與週期性追蹤。

職員｜策略教育

先理解 A 的方向，再從 C、D 看自己的工作如何產生下一個結果，以及公司為什麼強調 Stage、品質、改善與跨部門合作。

主管模式｜閱讀這一版時請抓住：
  • 每一個部門計畫都要能向上連回戰略計畫，並向下落到具體交付物與每週行動。
  • 不要把 C 當成工作清單；真正要管理的是結果、Stage、完成指標、Blocker 與跨部門資源。
  • D 的用途是把關鍵行為變成可持續的管理節奏，而不是額外增加一場活動。
董事會模式｜閱讀這一版時請抓住：
  • A 是上位方向與經營目標；B 是企業主在有限資源下做出的核心選擇。
  • 董事會不需要深入每一個工作步驟，但要檢查 C 的戰術組合是否有效支撐 B 的戰略。
  • 所有重大資源配置與優先順序，都應能回到 2030 四大目標與當前企業天花板。
職員模式｜閱讀這一版時請抓住：
  • 先知道公司要去哪裡，再理解自己的工作支援哪一個產品、客戶、品質或能力目標。
  • 公司未來更重視『有沒有產生下一個結果』，不只看做了多少活動或完成多少工作項目。
  • 當跨部門合作、CRM 紀律、品質與持續改善被要求時，都能在 A→B→C→D 中找到原因。

A｜企業擴展藍圖

先回答「我們最終要成為什麼？」

董事會應聚焦：
  • 願景與 2030 四大目標是否仍是資源配置的上位基準。
  • 三大產品線的 2030 基礎盤已約 11 億，因此 10 億應視為最低門檻。
  • 海外據點與上櫃不是獨立專案，必須與客戶、供應鏈、治理成熟度連動。
主管應聚焦：
  • 把願景與 2030 經營目標轉成部門年度目標、KPI 與資源優先順序；每個部門計畫都要能說明支援哪一個上位目標。
  • 當短期效率、成本、品質與長期能力發生衝突時，主管要以願景、使命與價值觀作為判斷基準，而不是只追求眼前完成率。
  • 定期檢查部門工作是否仍與營收、一線車廠、海外據點、上櫃四大終點保持連結。
職員會看到的改變：
  • 工作不只看「完成任務」，還要知道這項工作支援哪一個 2030 目標。
  • 品質、客戶需求、創新、改善、共同成長與長期夥伴關係，是遇到取捨時的判斷基準。
  • 各部門年度計畫與 KPI 應能向上連回這張藍圖。
A 要讓大家記住的 3 件事
1｜終點KLC 要成為全球車用加熱的知名專業品牌與核心供應夥伴。
2｜價值我們不是只製造 Heater，而是幫客戶選對 Heating Solution 並可靠交付。
3｜衡量2030 用營收、一線車廠、海外據點、上櫃四個結果檢驗。
常見誤解願景不是 KPI；10 億也不是終點上限，而是最低經營門檻。
Vision

願景｜我們想成為的樣子

成為全球電動車用加熱器的知名專業品牌，以穩定可靠的品質，成為國際車廠與系統商長期信賴的核心供應夥伴。

它描述的是終局，不是年度 KPI。真正要形成的是「市場認得 KLC → 相信 KLC 專業與品質 → 願意把重要專案長期交給 KLC」。

Mission

使命｜我們為什麼值得存在

深入理解客戶的應用與加熱需求，以專業的加熱技術、客製化能力與嚴謹的品質管理，協助客戶選擇真正適合的加熱解決方案，降低成本與風險，創造長期穩定可靠的產品價值。

KLC 的差異不是「有 Heater 可以賣」，而是客戶一開始提出的規格不一定是最好的，我們要幫他選對方案並可靠地做出來。

Values

六個不能因壓力而犧牲的原則

品質優先

不以低價作為唯一競爭手段，設計、材料、製程到交付都以穩定可靠為底線。

站在客戶實際需求思考

不只照規格，而是理解應用、升溫、成本與品質條件。

創新

持續投入加熱技術、產品設計、應用開發與專利。

持續改善

產品、製程、品質與工作方式持續迭代。

共同成長

公司成長要帶動員工能力、收入與生活一起提升。

長期夥伴關係

不因短期利益犧牲與客戶、供應商及合作夥伴的信任。

B｜戰略計畫

不是做更多，而是做出幾個關鍵選擇

董事會應聚焦：
  • 真正瓶頸不是詢價量，而是 KLC 尚未完成「Tier 1 願意長期採用並大量量產」的身份轉換。
  • 資源要放在產品世代轉換、Tier 1 信任、成本競爭力、Automotive Capability 四個橋段。
  • 每一個戰略計畫案都應能說明它如何降低這些天花板。
主管應聚焦：
  • 先確認自己承接哪一個戰略計畫案，以及它正在解除哪個企業天花板；沒有戰略連結的工作，不應與關鍵計畫爭奪同等資源。
  • 把核心戰略轉成可分工的部門選擇：哪些必須自己掌握、哪些可以 Buy／Partner、哪些需要跨部門共同解題。
  • 主管會議要聚焦瓶頸、資源衝突與決策需求，不只回報完成了多少工作。
職員會看到的改變：
  • 「全部自己做」不再是預設答案；公司會更常使用 Make／Buy／Partner 的思考。
  • 跨部門合作會集中在高價值 Tier 1、下一代產品、成本與量產能力。
  • 遇到資源衝突時，優先支援能推動戰略瓶頸的工作。
B 要讓大家記住的 3 件事
1｜真正瓶頸不是詢價少，而是信任、量產經驗、成本與 Automotive 能力尚未成熟。
2｜產品接棒PTC 守基本盤，Flexible 擴應用，Non-PTC Coolant 成為主要成長引擎。
3｜供應模式核心技術、規格、品質、IP、客戶關係自己掌握；製造不必全部自己做。
常見誤解12 個戰略計畫案不是 12 個同等優先目標，而是執行同一核心戰略的分工。
1

Situation｜我們現在卡在哪裡？

缺少一線車廠成交案例；大型車廠合作經驗與市場信任不足；Non-PTC Coolant Heater 尚在驗證；PTC／Flexible 在大量市場受到原料與製造成本限制。

2

Root Cause｜真正原因不是「沒有詢價」

KLC 尚未完成從「能做車用 Heater 的供應商」到「一線車廠願意長期信任、採用並大量量產的核心供應夥伴」的身份轉換。營運端也仍偏向自行開發、自行製造、自行供應，成本結構不易支撐全球大型量產。

3

Purpose｜戰略目的

完成國際車用市場的身份與能力升級：掌握客戶需求、核心技術、產品定義、品質標準，同時有能力整合全球供應鏈完成交付。

4

Core Strategy｜核心選擇

PTC 維持核心現金流並管理世代收斂；Flexible 擴大應用；集中資源把 Non-PTC Coolant Heater 做成主要成長引擎；同時以 OEM＋Tier 1 開發、Automotive Capability 與全球供應鏈整合突破規模天花板。

C｜戰術計畫

主管如何執行、達成多少、如何追蹤？

董事會／主管／職員三視角
HOW TO READ C

把戰略轉成主管可以管理、團隊可以執行的計畫

C 的核心不是增加工作項目，而是把戰略轉成明確的完成指標、責任、時程與可追蹤的推進結果。

量化目標要達成多少成果？
完成指標什麼狀態代表真正完成？
責任與時程由誰在什麼期限內完成？
進度管理每週是否真的推進下一個結果？
C｜戰術計畫

把戰略變成主管可以分工、量化、追蹤的計畫

董事會應聚焦：
  • 不要只看落後指標（營收、量產台數），要看領先指標（Sample、Validation、Design-in、Nomination、Cost Down、平台與能力建設）。
  • C1–C8 不是八個平行專案，而是一個互相依賴的執行組合。
  • 規劃假設應每季依市場與實際 Pipeline 滾動更新，而不是僵化追數字。
主管應聚焦：
  • 戰術計畫是主管層的主要管理工具：每一項都要有明確行動、時程、責任人、交付物與可追蹤的完成指標。
  • 生產型計畫重點是量化產出與時間拆解；發展型計畫重點是從現況走到理想狀態的能力、流程、系統或工具變革。
  • 每週追 Execution、每月看 Performance；遇到 Blocker 要提出需要的跨部門支援或決策，而不是只標示延遲。
職員會看到的改變：
  • 專案會有更清楚的 Stage、Owner、Next Action、Due Date 與完成指標。
  • Coolant 不是看「寄了幾封信」，而是看專案有沒有從 Target 真正走到 Validation、Design-in、Nomination。
  • PTC、Flexible、供應鏈、品質能力與海外布局都有自己的年度交付物。
C 要讓大家記住的 3 件事
1｜領先指標Sample、Validation、Design-in、Cost Down、平台與能力建設，比短期營收更能預測未來。
2｜2027 Coolant是 Pipeline 建設年，不是大量營收年；Funnel 第一版為 8→6→4→2。
3｜執行節奏每週看 Execution、每月看 Performance、每季做 Strategy Review、每年回到 2030 Roadmap。
常見誤解戰術不是工作清單；每個戰術都要有明確完成狀態與量化結果。

D｜團隊遊戲

如何讓團隊持續推進關鍵行為？

董事會／主管／職員三視角
D｜團隊遊戲

把關鍵行為從要求，轉化為團隊主動推進

團隊遊戲不是額外的娛樂活動，而是把戰術計畫中的高價值行為轉成清楚、可追蹤、具有回饋的執行機制。

遊戲目標參與方式積分機制獎勵與驚喜
D｜團隊遊戲設計

把「應該做」轉化為團隊願意持續推進的行為

D 不是娛樂活動，而是把 C 的戰術行為做成有目標、有障礙、有競爭、有獎勵的團隊演練。

董事會應聚焦：
  • 遊戲化不是福利活動，而是把 Strategic Account 的高價值行為變成透明、可追蹤、可激勵的團隊節奏。
  • 積分權重必須持續反映商業價值：越接近 Design-in、Nomination，分數越高。
  • 正式啟動前仍需核定起迄日、參賽 Account、管理員與獎勵金額。
主管應聚焦：
  • 主管不是只看排行榜，而是確保積分規則真正強化戰術需要的高價值行為，並維持競爭公平與資料可信。
  • Week 0 要建立 Baseline；每週確認 Stage 證據、Next Action、Blocker 與跨部門責任，讓遊戲成為管理節奏的一部分。
  • 階段性驚喜用來強化正確行為；正式獎勵、參賽範圍與管理角色仍需依公司核定規則執行。
職員會看到的改變：
  • 每個 Strategic Account 形成跨部門專案小組，進度與積分公開透明。
  • 解決關鍵 Blocker 會獲得較高權重；只有活動量、但沒有 Stage 推進，不會形成高分。
  • CRM 資料完整與 Next Action 準時，納入遊戲機制，也同步形成日常管理紀律。
D 要讓大家記住的 3 件事
1｜評比重點評估專案是否實質推進到下一個 Stage，而不是比較活動量、寄信數或會議數。
2｜勝出標準總積分最高，且至少完成一次實質 Stage 推進。
3｜公平機制Week 0 凍結 Baseline，只計算啟動後的新進展；所有分數皆須有可查證依據。
常見誤解團隊遊戲的目的不是娛樂，而是把跨部門高價值行為轉化為透明、可持續追蹤的管理節奏。
12-week Rule

遊戲運作方式

參賽方式：每一個 Strategic Account／Tier 1 專案形成一個跨部門專案小組。

核心成員：BD／Sales、FAE、R&D、QA；PM、製造、採購視需要加入。

公平原則：Week 0 先凍結 Baseline Stage，只計算啟動後的新進展。

證據原則：Stage 分數必須有客戶、正式專案、樣品、驗證、CRM 或公司系統中的可查證證據。

Six Elements

為什麼這是一個真正可運作的團隊遊戲

自由

專案小組可依規則自主決定客戶推進順序、分工與問題解決方式。

障礙

真實 Tier 1 技術、品質、驗證、商務與供應鏈 Gate。

目標

12 週內持續推進高價值專案，建立可支撐 Nomination／Mass Production 的 Pipeline。

競爭

Strategic Account 專案小組公開進度與排名，維持良性競爭。

獎勵

優勝團隊公開表揚＋獎金或禮券，金額由公司核定。

驚喜

Validation、Design-in、重大 Blocker、連續準時可觸發非金錢 Surprise。

釐清關鍵字義，統一用詞，降低跨部門誤解與誤用。

正式定義優先
E｜知識定義

把關鍵字定義說清楚，讓討論更有效率

統一語言不是咬文嚼字，而是讓董事會、主管與同仁對同一個詞有相同理解，減少誤會與執行落差。

KNOWLEDGE DEFINITION FLOW

定義不是背名詞，而是建立共同語言

1｜正式定義先確認公司管理語言中這個詞的正式意思。
2｜用自己的話重述確認團隊不是只看懂文字，而是真的理解。
3｜實務應用把定義放回決策、計畫、會議與工作情境中使用。
使用原則：有正式定義時，以正式定義為準；目前正式知識沒有定義時，再補充一般性說明，並明確區分，避免把一般用法當成公司標準。
KEYWORD LOOKUP

關鍵字定義查詢

輸入中文或英文關鍵字，例如「戰略」、「使命」、「Target」、「Root Cause」。

願景／目標 Vision / Goal

正式定義

願景是企業在能量充沛、資源充足的狀況下，所追求的「理想狀態」、「成為的樣子」。它是企業未來最想達成的宏觀圖像，代表企業最終極的自我期許。

使用重點回答「我們不再被生存追著跑時，想成為什麼？」
常見誤用不要把年度 KPI、短期專案或單一營收數字直接當成願景。

使命／目的 Mission / Purpose

正式定義

使命是企業之所以存在的理由，是這個企業對其所屬「商業生態圈」的價值貢獻。它回答：「這間公司存在，是為了誰？要解決什麼問題？」

使用重點回答企業為誰存在、解決什麼問題，以及創造什麼價值。
常見誤用使命不是產品清單，也不是「今年要做什麼」的工作計畫。

價值觀 Values / Policy

正式定義

價值觀是企業在運作過程中「做選擇」時的判斷依據，是成員行為的準則與文化的核心。它們支撐著企業如何實現使命與朝向願景。

使用重點作為資源緊縮、壓力來臨或意見分歧時的判斷基準。
常見誤用避免只列漂亮形容詞；價值觀必須真的能影響決策與行為。

經營目標 Targets

正式定義

經營目標是企業在特定時期（如一年、季度）所設定的量化或質化目標，作為衡量戰術與營運成果的標準。

使用重點回答「這一段期間一定要看到什麼成果？」
常見誤用要有時期與可驗證成果，避免只有方向性口號。

戰略計畫 Strategic Plan

正式定義

戰略是一種「選擇」。戰略計畫是企業為了達成願景與使命，針對現階段瓶頸與企業天花板，所設計的一套整體路徑與行動方案。戰略是有限資源下的最佳選擇與取捨。

使用重點聚焦真正限制擴展的突破點，明確哪些先做、哪些不做。
常見誤用戰略不是工作清單，也不是把所有重要事情全部同時列入。

戰術計畫 Tactical Plan

正式定義

戰術是主管團隊為了執行戰略，將策略轉為可執行的具體行動計畫。它包含明確的達成標的、行動步驟、責任分工與時程等。

使用重點把戰略轉成主管可以管理、團隊可以執行與追蹤的計畫。
常見誤用不能只有活動項目；要有完成標的、責任與時程，並能連回戰略。

營運計畫 Operational Plan

正式定義

營運計畫是讓戰術可以在日常落地的具體操作規範與管理流程。它涵蓋排程、SOP、KPI 追蹤、工具應用等管理面要素。

使用重點回答「每週、每天現場應該如何運作，才能讓戰術落地？」
常見誤用營運不是另一套平行計畫；它應承接戰術中的步驟與目標。

生產型計畫 Production Plan

正式定義

設定特定期間內課程或部門需完成的產出目標（如銷售額、潛在客戶數、訂單數等）。

使用重點以明確量化指標與時間週期拆解目標，持續追蹤達成情況。
常見誤用量化目標與拆解方式需先確認，不應任意平均分配。

發展型計畫 Development Plan

正式定義

針對團隊擴編、人員配置、流程優化、系統建置等中期成長策略所制定的計畫。

使用重點先確認現況與理想狀態，再依差距建立執行標的、時程與交付物。
常見誤用不要只列任務；要先說清楚要從什麼狀態發展到什麼狀態。

Situation｜情況

正式定義

說明現階段遭遇到的問題與挑戰，想要解決突破的瓶頸，或是想要達成的目標。可以包含營運數據、圖表。

使用重點先把現況與需要突破的核心問題說清楚。
常見誤用避免把真正原因或解法直接寫進 Situation。

Root Cause｜真正的原因

正式定義

我認為造成這些情況的真正原因為何？

使用重點從表面現象往下追，辨識真正造成 Situation 的原因。
常見誤用不要把症狀、抱怨或單一事件直接當成根因。

Purpose｜戰略計畫的目的

正式定義

說明要處理真正的原因，所採取的行動、路徑或是方法。

使用重點回答「為了解決真正原因，我們要採取什麼路徑或方法？」
常見誤用Purpose 不是成果數字，也不是一般性口號。

Project List｜計畫案清單

正式定義

將分為幾個項目，列出要執行本戰略計畫，需要分工執行的計畫和行動。

使用重點把戰略轉成可分工、可承接的計畫案。
常見誤用沒有關聯的類別不需要為了格式而硬塞計畫案。
目前正式知識中沒有符合的定義。請改用其他關鍵字，或重新確認想釐清的管理概念。
WORDING CHECK

容易混淆的用詞

願景 vs 經營目標願景描述長期理想狀態；經營目標描述特定時期必須達成的量化或質化成果。
戰略計畫 vs 策略事務計畫案戰略計畫是企業主的整體選擇與路徑；策略事務計畫案是執行該戰略時的一種計畫案分類，兩者不是同一層級。
戰略 vs 戰術戰略決定突破方向與取捨；戰術把戰略轉成具體標的、行動、責任與時程。
戰術 vs 營運戰術是為了執行戰略的具體計畫；營運是讓戰術在每天、每週落地的管理方式。
生產型 vs 發展型生產型聚焦量化產出；發展型聚焦組織、流程、系統、工具或能力的狀態改變。
活動量 vs 結果做了多少工作不等於產生進展；管理上要看是否形成可驗證的下一個結果。
